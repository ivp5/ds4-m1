# Generate the optimized model pack

One-time setup for DeepSeek-V4.1-Flash-1017 on Apple Silicon. Run these commands
from the repository root. After setup, start with `./ds4-agent`; no wrapper or
profile selection is needed.

## What needs disk space?

The base GGUF stays where it already is. The following are **additional local
files**, generated by this fork's tools; they are not tracked in Git and are not
files supplied by antirez's download script. `PACK` can be any writable directory
on your fast model SSD. The default is `gguf/ds41/` inside this clone.

| File relative to `PACK` | Size | Purpose / source |
| --- | ---: | --- |
| `bs64_gateup.bin` | 99,090,448,384 B = **99.09 GB / 92.29 GiB** | Routed gate/up, 2-bit planes with group-64 scales; requires original FP4 tensors and input-importance statistics |
| `g32_down.bin` | 53,791,965,184 B = **53.79 GB / 50.10 GiB** | Routed down, group-32 layout; requantized from the Q2_K GGUF |
| `dense.bin`, `dense.idx` | about 4.19 GB plus a small index | Dense Q4L weights; generated from the GGUF and calibration statistics |
| `ela_fit5h2_v2.bin` | 152,666,112 B | Fitted router lookahead for SSD prefetch |
| `bank.txt`, `shortlist.txt` | hundreds of bytes / about 0.2 MB | Drafter expert IDs and vocabulary IDs |
| `draft/DeepSeek-V4.1-Flash-DSpark-support.gguf` | about 4.50 GB | The checkpoint's three prediction stages and draft head |
| `draft/dsp_q4l.bin`, `draft/dsp_q4l.idx` | 356,012,032 B plus a small index | Q4L draft dense weights |

**BS64 + G32 alone add 152.88 GB / 142.39 GiB.** The complete derived pack adds
about 162.1 GB. With the 365.7-GB base GGUF, active model files total about
527.8 GB, before source checkpoint shards and temporary calibration captures.
These are logical on-disk sizes, not RAM requirements. Builders print their
output size before encoding, refuse existing outputs and check free disk space.
Interrupted `.part` files need inspection before retrying; no automatic resume
is promised for these overlay builders.

The small calibration bundle in `gguf-tools/calibration/` is about **10.94 MB**:
compressed named dense statistics, a derived 1.64-MB BS64 importance table,
a generic drafter bank, and provenance/checksums. It contains aggregates and
publicly authored calibration prompts, not private conversations or evaluation
inputs. It saves dense/BS64 calibration capture and bank collection. **The BS64
importance and generic bank differ from the historical measured pack; their
end-to-end speed and fidelity have not yet been validated.** The fitted lookahead
still needs independent calibration trajectories. See
[the calibration manifest and limitations](../gguf-tools/calibration/README.md).

## Build the assets

The commands below generate a complete pack. Python 3.10+, NumPy and SciPy are
needed for builders; optional PyTorch on a CUDA/ROCm machine accelerates BS64
encoding. Build the C converter with the compiler already used for ds4.
Install Python dependencies in your preferred environment using
`python3 -m pip install -r gguf-tools/requirements.txt`.

Set these paths yourself; none refers to a maintainer's private directory:

```sh
MODEL=/absolute/path/to/DeepSeek-V4.1-Flash-Q2.gguf
HF=/absolute/path/to/DeepSeek-V4.1-Flash-1017-source
PACK="$PWD/gguf/ds41"
CAL="$PACK/calibration-captures"
REV=1bae0e1088993b9b82de08f59de5be5a34e42170
mkdir -p "$PACK/draft"
make -C gguf-tools -j2
```

This profile requires **DeepSeek-V4.1-Flash-1017**, 40 layers, 384 experts,
width 5120: IQ2_XXS routed gate/up, Q2_K down and Q8_0 dense weights in the
base GGUF. For other upstream models, set `DS4_PROFILE=upstream`.
`HF` contains `config.json`, `model.safetensors.index.json`, and relevant weight
shards from `deepseek-ai/DeepSeek-V4.1-Flash-1017` at `REV`. Match the base model
and source checkpoint revision. The model's license applies to its weights.
You cannot recover the original FP4 weights from an already quantized Q2 GGUF.

If you already have the matching base GGUF, **skip base conversion**. Otherwise
use the included upstream converter, with independently collected imatrix data
if available; omitting it uses weight-energy weighting and need not reproduce
someone else's quantized weights:

```sh
python3 gguf-tools/deepseek41_quantize.py --hf "$HF" --out "$MODEL" --source-revision "$REV" --quant q2 --threads 4
```

For an existing GGUF, you need only source shards containing BS64 inputs and
prediction-stage tensors. List those from the downloaded index; fetch the listed
files at the same revision with your Hugging Face client. Shards can also contain
unrelated tensors, so this list is not a promise of minimal byte ranges:

```sh
python3 gguf-tools/list_shards.py --index "$HF/model.safetensors.index.json" --component bs64
python3 gguf-tools/list_shards.py --index "$HF/model.safetensors.index.json" --component draft
```

Generate the three main overlays using the bundled statistics. Add `--plan` to
each command first for a metadata/size check without writing model weights.
These are lossy weight representations, not lossless compression:

```sh
python3 gguf-tools/build_bs64.py --hf "$HF" --model "$MODEL" --importance gguf-tools/calibration/importance.npy --revision "$REV" --out "$PACK/bs64_gateup.bin"
python3 gguf-tools/build_g32.py --model "$MODEL" --out "$PACK/g32_down.bin"
python3 gguf-tools/build_dense.py --model "$MODEL" --stats gguf-tools/calibration/dense_means.npz --out "$PACK/dense.bin"
```

For BS64 on a separate CUDA/ROCm machine, pass `--device cuda`. The builder first
requires byte equality against the NumPy codec on a canary matrix. Transfer the
result and its adjacent `.json` receipt, not the source checkpoint, to the Mac.
G32 needs no activation calibration. Its verifier tests sampled conversion
agreement and a corruption canary; that is not a model-quality test.

Generate the draft support model and its dense overlay:

```sh
gguf-tools/deepseek4-quantize --hf "$HF" --dspark-support --dspark-target-layers 37,38,39 --source-revision "$REV" --out "$PACK/draft/DeepSeek-V4.1-Flash-DSpark-support.gguf"
python3 gguf-tools/build_dense.py --model "$PACK/draft/DeepSeek-V4.1-Flash-DSpark-support.gguf" --draft --out "$PACK/draft/dsp_q4l.bin"
cp gguf-tools/calibration/bank.txt "$PACK/bank.txt"
```

Collect lookahead training trajectories on the bundled generic prompts. This
runs the model on the Mac, one session at a time; do not run beside another
model job. Keep calibration prompts disjoint from every task used to evaluate
performance or quality. Captures can approach a gigabyte for the default eight
256-token sessions. The fit can run on another machine using the captures and
matching GGUF:

```sh
python3 gguf-tools/calibrate.py --model "$MODEL" --out "$CAL"
python3 gguf-tools/build_lookahead.py --model "$MODEL" --captures "$CAL"/*.xcap --out "$PACK/ela_fit5h2_v2.bin"
```

To regenerate rather than reuse the bundled calibration, `calibrate.py` accepts
`--prompts your-independent-prompts.json` (an array of strings). Its `dense.acts`
can replace `dense_means.npz`. Create BS64 importance with:

```sh
python3 gguf-tools/build_importance.py --captures "$CAL"/*.xcap --out "$PACK/importance.npy"
```

To rebuild the drafter bank, run calibration into a **new** directory with
`--draft "$PACK/draft/DeepSeek-V4.1-Flash-DSpark-support.gguf"`, then pass its
`*.counts` files to `gguf-tools/build_bank.py --counts ... --out ...`.
For the vocabulary shortlist, supply a reasonably broad, independent UTF-8
code/prose corpus. The command tokenizes it with this engine; it does not train
on your future evaluation tasks:

```sh
python3 gguf-tools/build_shortlist.py --model "$MODEL" --corpus /absolute/path/to/public-calibration-corpus.txt --out "$PACK/shortlist.txt"
```

Validate the generated pack and start the agent:

```sh
python3 gguf-tools/assets.py --model "$MODEL" --assets "$PACK" --program agent
./ds4-agent -m "$MODEL"
```

Assets default to `gguf/ds41/` beside the executable. If you chose a different
location, set `DS4_MODEL_DIR` to that directory. Symlink your existing GGUF to
`ds4flash.gguf` once to omit `-m` on subsequent runs. The engine lists missing
selected assets and refuses to silently run an incomplete optimized profile.

Keep each builder's `.json` receipt with its output. Receipts bind file size and GGUF header
identity; they are **not full weight-content checksums**. Q4L index payload paths
are relative to the index, so moving the whole pack does not break them.
